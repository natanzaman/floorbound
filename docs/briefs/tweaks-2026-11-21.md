# Owner calls 2026-11-21 (`feat/tweaks`)

Two changes from the 2026-11-20 batch's open questions; everything else on that list stays as is.

## 1. Several of the Named in one party
Owner: yes. A party may hold any of the Named (the four Hearthward and Cairn) up to the normal `PARTY_MAX` (6).
Each Named still exists once in the world.

Plan (server/named.js, server/namedquests.js; data in shared/named.js):
- One helper `partyRoom(h, st)`: "Your party is full." when h's party, plus the other Named holding h's invite (they
  could accept at any moment), already reaches `PARTY_MAX`. It replaces "One of the Named per party" in
  `inviteBlock`, `callBlock` and `namedquests.joinBlock`; outreach (`outBlock`) only skips a full party.
- Accepting re-checks through `onInvite` as before (now: party room); `game.joinParty` still refuses a full party.
- Despawn / respawn: `rejoinHost` and `runPending('rejoin')` drop the "no other Named" condition (room still checked).
- Free Named left in a party with no human (the human left a party of two Named): the group logic already sorts it
  (the Hearthward regroup, Cairn leaves); checked in a test.
- Going home: each Named keeps its own quiet timer (`withHost`), unchanged; boss plans count a group short-handed
  when one of them is with a human (unchanged); friendship gains already loop every Named in a fight / kill.
- The unused "taken" lines and `namedInvited` go. UI text: README, guide, ROADMAP / NEXT.

Tests: test/named.js (the old "one per party" checks become "two in one party"; three Named + three humans = full),
test/freebots.js (invite two from the list, despawn / respawn one rejoins beside the other, the party limit).

## 2. Weapon attack field of view (`mods.fov`)
Rule of thumb (owner): wider swings with slower attacks, narrower with quicker ones. Data only, in shared/styles.js;
defaults stay 1 (the baseline). `mods.fov` scales the half-angle of the style's arc attacks (style arc basics, the
Swordsman / Berserker class arcs and arc skills that read `atkFov` half: slash, Burst Combo and its evolutions, chop,
the Cleave skill, Executioner). Lines, rings, bolts, chords and Hamstring have no fov half, so ranged / caster / thrust
styles stay 1. Values from each style's basic-attack cooldown against its class default:

| Style | Basic cd vs default | fov |
| --- | --- | --- |
| Dual Blades | 0.4 s vs 0.55 s | 0.85 |
| Rapier | 0.6 s thrusts (precise; arcs: Burst Combo) | 0.9 |
| Twin Daggers | 0.4 s vs Shot 0.6 s | 0.85 |
| Twin Axes | 0.55 s vs 0.85 s | 0.9 |
| Mace & Shield | 0.95 s vs 0.7 s | 1.15 |
| Halberd | 0.7 s sweeping arcs vs 0.6 s thrusts | 1.15 |
| Warhammer | 1.25 s vs 0.85 s | 1.2 |
| everything else | lines / rings / bolts / ranged / default | 1 |

Glaive is slower (0.7 s) but every attack it has is a line, so a multiplier would do nothing: 1.
Cleave caps and the Cone filter are applied after the arc (capHits) and don't read fov: tests check both still hold.
Tests: test/targeting.js (a 1.2 style hits a mob a 1.0 style misses at the edge, a 0.85 style misses one a 1.0 hits;
the cap and Cone filter with a widened arc), styles, combat, classes-a, classes-b.
